# Support

## Before Asking

Read the [README](./README.md), check existing issues and discussions, and confirm that you are using the latest available build. A clear report helps other users find the answer later.

## Usage Questions

Start a GitHub Discussion or open an issue with the `question` label. Include:

- Percolume version or commit
- Windows version and display scaling
- What you were trying to do
- What happened and what you expected
- Steps that reproduce the problem

## Bug Reports

Use the bug report template for reproducible failures. Include relevant console output or screenshots, but remove private notes, local exports, and personal information first.

## Feature Discussions

Describe the user problem before suggesting an implementation. Explain who is affected, how often it occurs, and what a useful result would look like.

## Security And Privacy

Do not post security vulnerabilities or private progress data publicly. See [SECURITY.md](./SECURITY.md) for vulnerability reports.
